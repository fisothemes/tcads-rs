# TwinCAT ADS I/O

The network transport engine for the **TwinCAT AMS/ADS** protocol.

This crate takes the pure protocol byte-buffers generated by `tcads-core` (`AmsFrame`) and pushes them across the network. It handles TCP framing, length-prefix parsing, and socket splitting, allowing you to easily build concurrent, robust TwinCAT clients.

## Features

- **Runtime Flexibility:** Provides fully-featured implementations for both synchronous (`std::io` / `std::net`) and asynchronous (`tokio::io` / `tokio::net`) environments.
- **Transport Agnostic:** The stream wrappers are generic over `Read + Write` (or `AsyncRead + AsyncWrite`). While TCP is the default, you can easily tunnel ADS traffic over **TLS**, **Unix Domain Sockets**, **Serial Ports**, or **in-memory buffers** for testing.
- **Concurrent I/O:** Streams can be split into independent `AmsReader` and `AmsWriter` halves, allowing a background task to constantly read incoming router notifications while the main thread writes requests.
- **Robust Framing:** Automatically buffers incoming bytes, handles partial network reads, and yields complete, validated `AmsFrame` objects.

## Usage

This crate is designed to be paired closely with `tcads-core`, which provides the `AmsFrame` type and the typed protocol builders.

### 1. Blocking I/O: Listening to a stream

By splitting the stream, you can create a dedicated loop that listens to incoming ADS traffic, which is essential for receiving asynchronous notifications (like device state changes or symbol subscriptions) over the TwinCAT AMS router.

```rust
use tcads_io::blocking::AmsStream;
use tcads_core::ams::AmsCommand;
use tcads_core::protocol::{
    PortConnectRequest, 
    PortConnectResponse,
    RouterNotification
};

fn main() -> Result<(), Box<dyn std::error::Error>> {
    // Connect to the AMS Router and disable Nagle's algorithm automatically
    let stream = AmsStream::connect("127.0.0.1:48898")?;
    
    // Split into independent reader and writer
    let (reader, mut writer) = stream.try_split()?;

    // Send a handshake request
    writer.write_frame(&PortConnectRequest::default().into_frame())?;

    // Process the incoming frame stream indefinitely (similar to TcpListener)
    for result in reader.incoming() { 
        let frame = result?;
        
        match frame.header().command() {
            AmsCommand::PortConnect => {
                let resp = PortConnectResponse::try_from(&frame)?;
                println!("Connected! Assigned address: {}", resp.addr());
            }
            AmsCommand::RouterNotification => {
                // Sent by the router when the PLC changes from RUN to CONFIG
                let notif = RouterNotification::try_from(&frame)?;
                println!("AMS Router state changed: {:?}", notif.state());
            }
            _ => {
                println!("Received unknown frame: {:?}", frame.header().command());
            }
        } 
    }

    Ok(())
}
```

### 2. Async I/O (Tokio): Request and Response

The `tokio` module provides an identical API adapted for `async`/`await`.

```rust
use tcads_io::tokio::AmsStream;
use tcads_core::ams::AmsCommand;
use tcads_core::protocol::{PortConnectRequest, PortConnectResponse};

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let stream = AmsStream::connect("127.0.0.1:48898").await?;
    let (mut reader, mut writer) = stream.into_split();

    // Write a request
    let request = PortConnectRequest::default();
    writer.write_frame(&request.into_frame()).await?;

    // Await the response frame
    let response_frame = reader.read_frame().await?;
    
    if response_frame.header().command() == AmsCommand::PortConnect {
        let response = PortConnectResponse::try_from(&response_frame)?;
        println!("Router assigned us the address: {}", response.addr());
    }

    Ok(())
}
```

### 3. Custom Transports (e.g., In-Memory Buffers)

Because `AmsStream` is generic, you aren't locked into standard network sockets. You can use any type that implements standard I/O traits.

```rust
use std::io::Cursor;
use tcads_io::blocking::AmsStream;
use tcads_core::{AmsCommand, AmsFrame};

fn main() -> Result<(), Box<dyn std::error::Error>> {
    // Wrap an in-memory buffer (useful for unit testing protocol logic)
    let mock_socket = Cursor::new(Vec::new());
    
    let mut stream = AmsStream::new(mock_socket);
    let frame = AmsFrame::new(AmsCommand::PortConnect, [0x00, 0x00]);
    
    // Writes the framed bytes seamlessly into the Cursor
    stream.write_frame(&frame)?;
    
    Ok(())
}
```
